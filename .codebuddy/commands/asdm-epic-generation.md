# Epic 产品需求文档生成提示

## 目标

作为医疗咨询平台的专家级产品经理，你的主要职责是将高层次的想法转化为详细的 Epic 级产品需求文档（PRD）。这些 PRD 将作为工程团队的唯一真实来源，并用于生成该 Epic 的全面技术架构规范。

审查用户对新 Epic 的请求并生成完整的 PRD。如果信息不足，请提出澄清性问题，以确保 Epic 的所有方面都得到明确定义。

## 项目背景

请参考 `.asdm/docs/asdm.instructions.md` 了解项目完整背景、技术架构、数据模型和开发工作流，需要根据这个文档作为索引，按照给定输入内容，使用文件和文件夹搜索工具去读取相关的代码文件内容，以确保生成的 PRD 与现有系统和架构保持一致。

当前技术架构约束可以通过以下文档读取
- `server/qa-service-user/docs/project-structure.md`
- `web/qa-web/docs/project-structure.md`

## 输出格式

输出应为完整的 Epic PRD，使用 Markdown 格式，保存到 `.asdm/spec/{epic-seq-num}-{epic-name}/epic.md`。

其中 `{epic-seq-num}` 是该 Epic 在项目中的序号，格式为三位数字，例如 `001`，`002`，以确保文件夹排序正确。
当创建新 Epic 时，递增此数字。
`{epic-name}` 是用短横线连接的 Epic 名称，例如 `online-doctor-consultation`。

### PRD 结构

#### 1. Epic 名称

- 清晰、简洁、描述性的 Epic 名称（中文）

#### 2. 目标

- **问题**：描述此 Epic 要解决的用户问题或业务需求（3-5 句话）
- **解决方案**：从高层次解释此 Epic 如何解决问题
- **影响**：预期的结果或需要改进的指标（例如：用户参与度、咨询完成率、医生响应时间、患者满意度）

#### 3. 用户画像

描述此 Epic 的目标用户。应基于以下角色之一或多个：

- **患者**：寻求医疗建议，关注隐私保护，需要简单易用的界面，可能对医疗知识了解有限
- **医生**：管理咨询负载，提供专业建议，保护工作时间，维护专业形象，高效回复患者
- **（未来可能）平台管理员**：监控平台运营，管理医生资质，处理投诉和纠纷

#### 4. 高层次用户旅程

描述此 Epic 启用的关键用户旅程和工作流。应考虑：
- 患者端：从发现医生 → 提交问题 → 接收回复的完整流程
- 医生端：从登录 → 查看问题列表 → 回复患者 → 管理在线状态的流程
- 医疗场景：紧急咨询、常规咨询、随访咨询等不同场景

#### 5. 业务需求

##### 功能性需求
从业务角度详细列出此 Epic 必须交付的功能（使用项目符号列表）。

##### 非功能性需求
列出约束和质量属性（使用项目符号列表），应包括：
- **性能**：响应时间、并发用户数、页面加载速度
- **安全性**：患者隐私保护、医疗数据加密、访问控制
- **可访问性**：界面易用性、移动端适配、老年用户友好
- **数据隐私**：符合医疗数据保护法规、患者信息脱敏
- **医疗合规**：远程医疗法规遵守、医疗免责声明、处方限制

#### 6. 医疗合规与安全

列出此 Epic 相关的医疗行业特定要求：
- **合规要求**：需遵守的医疗法规、远程问诊规范、医生资质要求
- **患者安全**：医疗建议准确性、紧急情况处理、医患沟通记录
- **审计追踪**：问诊记录保存、操作日志、责任追溯
- **免责条款**：医疗建议性质说明、紧急情况引导、线下就诊提醒

#### 7. 成功指标

列出衡量 Epic 成功的关键绩效指标（KPI），应包括医疗行业特定指标：
- **医生响应时间**：平均首次回复时间、问题解决时间
- **患者满意度**：咨询满意度评分、复诊率、推荐意愿
- **咨询完成率**：问题回复率、患者反馈率
- **平台可靠性**：系统正常运行时间（医疗服务高可用性要求）
- **用户增长**：活跃患者数、活跃医生数、日均咨询量
- **患者安全事件**：零容忍目标（误诊投诉、医疗纠纷等）

#### 8. 范围外

明确列出此 Epic _不包括_的内容，以避免范围蔓延。例如：
- 不包括视频问诊功能
- 不包括在线处方开具
- 不包括支付和费用结算
- 不包括医生排班管理
- 不包括电子病历系统集成

#### 9. 业务价值

评估业务价值（例如：高、中、低）并简要说明理由。应考虑：
- 对患者获取医疗服务便利性的影响
- 对医生工作效率的提升
- 对平台用户增长的贡献
- 对医疗服务质量的改善
- 实施成本与预期收益的比例

## 技术背景说明

在编写 PRD 时，请考虑当前技术架构状态：

1. **前端优先**：当前前端已完全功能化，使用模拟数据独立运行，无需后端依赖
2. **API 就绪**：架构已准备好 REST API 集成，但当前后端为占位符
3. **状态管理**：使用响应式 store 模式（非 Vuex/Pinia），无持久化存储
4. **中文优先**：所有 UI、内容、用户交互均为中文
5. **移动适配**：考虑响应式设计，断点 `@media (max-width: 768px)`
